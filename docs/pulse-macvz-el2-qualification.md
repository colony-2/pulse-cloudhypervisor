# ARM64 provider-reboot testing on macOS/VZ

On November 24, 2026, the project received platform feedback that the current macOS/VZ stack supports the deployed L2 workload but does not support the hardware-accelerated L3 guest required by the proposed reboot test. This resolves the earlier request to try `kvm-arm.mode=nested` on a canary. On the deployed Ubuntu worker, Linux reported KVM API version 12 and `KVM_CAP_ARM_EL2=0`. [Deployed worker probe](http://db.lab.c2.run:8081/project/c2/jobs/3MWUYi0KZTuYXTAdaQX6YYs0aax/story)

In ordinary operation, macOS (L0) runs the Ubuntu worker (L1), and Cloud Hypervisor on that worker boots a workload VM (L2). The retired LIVE-09 test called for L1 to boot a disposable provider VM at L2. That provider would have to boot a workload at L3 before L1 could reboot the provider and observe recovery of its original state. This topology exceeds the platform limit.

Commit `5ac5026` passed all 78 local requirements and all ten retained native requirements on one worker. The project removed LIVE-09 from acceptance. Current verification uses the ordinary L1 provider and L2 workload.
