# ARM64 provider-reboot testing on macOS/VZ

On November 24, 2026, the project received platform feedback that the current macOS/VZ stack supports the deployed L2 workload but does not support the hardware-accelerated L3 guest required by the proposed reboot test. This resolves the earlier request to try `kvm-arm.mode=nested` on a canary. On the deployed Ubuntu worker, Linux reported KVM API version 12 and `KVM_CAP_ARM_EL2=0`. [Deployed worker probe](http://db.lab.c2.run:8081/project/c2/jobs/3MWUYi0KZTuYXTAdaQX6YYs0aax/story)

In ordinary operation, macOS (L0) runs the Ubuntu worker (L1), and Cloud Hypervisor on that worker boots a workload VM (L2). For LIVE-09, L1 would instead boot a disposable provider VM at L2. That provider would have to boot a workload at L3 before L1 could reboot the provider and observe recovery of its original state. The platform limit blocks this test topology.

Commit `5ac5026` passed all 78 local requirements and all ten other native requirements on one worker. LIVE-09 remains blocked and full acceptance remains open. Testing recovery requires a placement that supports the extra level or a revised test design in which an external observer can reboot a disposable provider host running a real workload VM.
